# Google DLB：面向生成式 AI 推理的大规模分布式负载均衡设计思想与方案深度解析

> [!info] 算力网络架构手记 · Inbox · 2026-10-14 07:35 · [原文](https://mp.weixin.qq.com/s/73rkfe-LbT1D3gj9nrSuZw)

## 1\. 概述与核心愿景

### 1.1 系统定位与工程背景

Google DLB（Distributed Load Balancer at Scale for Generative AI Inference）是 Google 为应对生成式人工智能（GenAI，如 Gemini 等大语言模型）以及复杂机器学习模型在超大规模云端集群部署所设计的专有 Layer 7（应用层）全局分布式负载均衡系统。

DLB 于 2024 年末起全面接替 Google 原有的集中式全局负载均衡器（MNLB），作为 Google 核心大模型与机器学习推理服务的基础网络底座，纳管全球数百个数据中心（Cells）以及数以百万计的机器学习加速卡（MLA，如 TPU 与 GPU）。

### 1.2 核心设计思想与终极目标

在大规模异构智算集群中，负载不均衡会带来极其高昂的资本浪费：部分数据中心算力出现排队拥塞，而另一部分数据中心算力却处于相对闲置状态。

DLB 的核心设计思想是：**“拉平时延-利用率曲线（Flatten the Latency-Utilization Curve）”**。

- **在固定算力容量下**

  通过毫秒级的跨域与域内两级协同调度，将全网请求合理分流，显著压缩队列等待时间，降低端到端服务延迟（特别是 P90/P95/P99 长尾延迟）。

- **在固定时延 SLA 目标下**

  降低系统为抵御流量突发而不得不预留的保守安全冗余（Headroom），使整体智算集群能够在极高利用率（Run Hot）状态下稳定运行，最大化压榨高成本 MLA 芯片的算力价值。

## 2\. 业务背景与传统方案的失效根因

### 2.1 云端大模型推理的四大独特性挑战

与传统无状态 Web 服务或微服务相比，生成式 AI 推理呈现出以下四个本质维度的挑战：

1. **时延跨越多个数量级（“细沙 Sand”与“巨石 Boulders”混杂）**
   \* **细沙请求（Sand）**：毫秒级响应的轻量短请求（如推荐模型、高频短文本分类）。
   \* **巨石请求（Boulder）**：超长上下文 Prefill 或深度推理链（Reasoning）任务，单次计算耗时可达数秒甚至数分钟。
   \* 对于巨石任务，服务本身的计算开销远远高于广域网传输延迟（RTT），此时将请求跨域调度到异地空闲数据中心消化积压，在经济性和性能上具备极高价值。

2. **算力安全冗余（Headroom）极其昂贵且稀缺**
    \* 传统 Web 服务通常可以通过超量配给（Over-provisioning）廉价的通用 CPU 算力来吸收流量突发。
    \* MLA 加速芯片不仅采购和运维成本极其昂贵，而且受制于物理供应链与电力供给，无法随意冗余。系统必须常态化维持在极高利用率下运行。

3. **硬件代际异构与复杂服务栈演进**
   \* **硬件异构**：不同数据中心内加速卡代际（如不同世代 TPU/GPU）混部，算力差距可达数倍至一个数量级。
   \* **复杂引擎演进**：推理运行时广泛采用了连续批处理（Continuous Batching）、Prefill-Decode 分离（PD 分离）及投机解码等技术，计算表现出复杂的非线性行为。相同的在途请求数（RIF）在不同节点对应的真实响应时延截然不同。

4. **广域网延迟反馈滞后与流量震荡（Herding & Oscillations）**
   \* 广域网传输往返时延（RTT）使得控制平面获得的数据状态天然滞后。
   \* 若调度器将流量激进切向当前显示空闲的数据中心，在该决策的影响通过网络反馈回调度器之前，该数据中心极易被持续涌入的请求直接冲垮。这种滞后反馈会导致流量在不同地域间剧烈振荡（羊群效应）。

### 2.2 传统负载均衡方案失效根因对比

| 方案类型           | 代表技术                               | 工作层级    | 致命缺陷与在 GenAI 场景下的失效原因                                                                                        |
| -------------- | ---------------------------------- | ------- | ------------------------------------------------------------------------------------------------------------ |
| **四层网络负载均衡**   | Maglev、Ananta 等                    | Layer 4 | 基于数据包五元组和一致性哈希转发，完全缺乏 L7 应用语义感知能力。其建立在“请求计算开销同质”的假设上，无法感知大模型的 Prompt 长度、生成 Token 数及 GPU 队列积压。                |

| **传统集中式全局均衡器** | Google MNLB                        | 全局控制面   | 依赖中心化优化器周期性计算全局路由权重，控制回路长达数十秒级（tens-of-seconds）。面对以毫秒/秒级暴冲的 AI 推理流量，策略调整严重滞后；且仅将时延视作隐式约束，依赖运维保留高昂的 Headroom。 |

## 3\. DLB 系统总体架构与组件分工

DLB 摒弃了传统的集中式慢控制环路与无感知转发模式，构建了一套两层（Two-Tier）分布式解耦架构。

![[Google DLB：面向生成式 AI 推理的大规模分布式负载均衡设计思想与方案-01.png]]

### 3.1 核心层级与网络拓扑

- **Cell（数据中心单元）**

  DLB 管理的基本地理与算力部署单元，内部部署有一组推理服务器（Inference Server，配备 GPU/TPU），以及运行在该 Cell 内部的多个 Root Router 和 Leaf Router 副本。

- **Eligible Cells（合规候选集合）**

  受限于法规合规与数据安全边界（数据驻留约束 Traffic-Residency Constraints，如欧盟 GDPR 要求某些个人数据不得出境），特定客户端发起的请求仅能在合规的子集内调度。

- **Root Router（全局根路由器）**

  部署在靠近客户端接入侧的 Cell，拥有全局视图。负责将请求即时转发（Dispatched）至最优目标 Cell 的 Leaf Router。Root 路由器为纯无状态设计，**绝不积压或排队请求**。

- **Leaf Router（域内叶路由器）**

  部署在各目标 Cell 内部，负责接收来自 Root Router 的请求，并通过微观调度下发给 Cell 内的具体推理服务器；同时采集本域服务指标并拟合时延模型。

### 3.2 路由器内部核心模块分工

#### 1\. Root Router 内部模块

- **全局路由算法（Global Routing Algorithm）**

  综合当前可用候选 Cell 集合中的成本函数，根据任务类型调用离散路由或流式概率路由算法，决定目标 Cell，并轮询发往该 Cell 内的某台 Leaf Router 副本。模块内建动态避错机制（Error Aversion），自动降权错误率上升的节点。

- **探针客户端（Probe Client）**

  以毫秒级频率向各候选 Cell 的 Leaf Router 发送主动探针。同一 Cell 内的多台 Root Router 采用\*\*“轮流探针”\*\*机制，一人探测，通过 P2P 通信在同域 Root 副本间共享响应，最大化降低广域网探针开销。

#### 2\. Leaf Router 内部模块

- **局部路由算法（Local Routing Algorithm）**

  采用轻量级 Power-of-d-Choices（P2C，生产环境中取）机制，快速比对随机抽取的推理服务器队列深度，分配计算任务。同时负责记录请求时间戳并统计错误率。

- **时延估计器（Latency Estimator）**

  收集本 Cell 内的请求到达与完成时间戳，采用在线非线性回归拟合参数化的 **Softplus 时延模型**，将微观排队与硬件特性抽象为连续函数。同域多个 Leaf 副本同样采用\*\*“轮流估算”\*\*和 P2P 广播同步参数。

- **探针服务端（Probe Server）**

  响应来自 Root Router 的探针请求，以异步缓存方式毫秒级返回当前 Cell 的在途请求数（RIF）、Softplus 模型参数及错误率。

## 4\. 核心路由算法与数学模型体系

### 4.1 双轨全局路由机制

针对大模型负载时延跨越数量级的特征，Root Router 实现了针对“巨石”与“细沙”的双轨路由机制：

#### 1\. 离散路由（Discrete Routing）—— 适配“巨石”（Boulders）

对于长文本 Prefill 和复杂链式推理，单次计算长达数秒至数分钟，广域网传输 RTT（几十毫秒）占比极小。

### 4.2 三大成本评估函数（Cost Functions）

系统支持针对不同场景配置以下三种成本评估函数：

1. **基于 RIF 的成本（RIF-based Cost）**

      （为在途请求数，为目标 Cell 的服务器副本数）。
   \* **特性**：追求各数据中心人均在途负荷对齐。无需时延估计，对硬件速度与网络 RTT 盲视，主要用作**新模型端点冷启动上线时的安全保底策略**。

2. **基于时延的成本（Latency-based Cost）**

      （为预期服务耗时，为广域网往返 RTT）。
   \* **特性**：追求单个请求端到端延迟最小，系统驱动全网达到博弈论中的 **Wardrop 均衡（Wardrop Equilibrium）**。

3. **基于梯度的成本（Gradient-based Cost）**

      （为数据中心在负载下的处理吞吐速率 Queries/sec）。
   \* **特性**：项度量节点靠近饱和区时的**边际延迟敏感度**。当算力趋近极限时，，成本呈现暴冲式攀升，形成天然的阻断壁垒。数学上证明该策略能使系统收敛至**全网平均延迟最小的社会最优解（System Optimum）**。

### 4.3 局部路由算法（Local Routing）

在 Leaf Router 内部，任务分配给具体 Inference Server 兼顾高吞吐与前缀缓存（Prefix Caching）：

- **Power-of-d-Choices (P2C)**

  随机抽取台服务器，比对它们待执行队列中的 Token 规模，规避全局排队轮询引发的锁竞争与惊群。

- **条件式前缀缓存粘性路由（Conditional Affinity Routing）**

  大模型多轮会话的前缀命中可大幅降低 Prefill 计算量。DLB 摒弃传统易引发单点过载的一致性哈希，实施**条件式粘性判定**：

$$
原 服 务 器 预 期 时 延 前 缀 命 中 节 约 开 销 候 选 服 务 器 预 期 时 延
$$

  仅在满足上述条件时保持会话粘性；一旦原节点排队严重，果断打破粘性重路由至其他服务器。

### 4.4 黑盒化 Softplus 时延模型拟合

针对 GPU/TPU 异构与连续批处理等黑盒执行栈，Leaf Router 采用平滑凸函数 Softplus 对时延进行参数化在线拟合：

- **物理特性解析**

  \* **在轻载区（较小）**：曲线渐近于平坦常数，准确表征硬件固有的单次模型前向执行开销（无排队延迟）。
  \* **在重载区（较大）**：曲线渐近于斜率为的线性增长，精准刻画队列堆积带来的非线性排队暴冲。

- **Little's Law 转换**

  利用稳态近似，得到服务速率函数，进而求导得出梯度成本所需的边际敏感度项。

## 5\. 关键技术机制与稳定性保障

### 5.1 带外探针机制与死锁打破

时延在线学习与流量分发闭环会引发两类经典控制论问题：

1. **右删减偏差（Censoring Bias）**

   滑动窗口若只统计已完成的请求，统计样本会系统性偏向轻量短任务，对重型长任务产生过分乐观的估计。DLB 引入在途驻留惩罚，修正长任务时延权重。

2. **饥饿死锁（Starvation Loop）**

   当某个 Cell 因瞬时抖动被判定为慢节点后，流量被完全切走；缺乏新流量便无法产生新样本，系统无法感知该节点是否已经恢复健康。

**破局方案**：

- **带外主动探针**

  Root Router 持续向 Leaf 发送毫秒级带外探测，与业务数据流解耦。

- **贝叶斯先验收缩（Bayesian Shrinkage）**

  缺乏样本时，将估算参数收缩拉回全网先验均值（Fleet-wide Prior）。

- **控制抖动噪声（Dithering）**

  注入细微扰动，主动探索边缘节点，打破探索与利用（Exploitation vs Exploration）死锁。

### 5.2 广域网延迟下的震荡抑制与数学收敛保证

为了在数学上证明流式概率路由在广域网 RTT 延迟下的绝对稳定性，DLB 建立了基于 Lyapunov 函数的理论框架：

- **步长约束准则**

  证明了更新步长必须与全网最大网络延迟成反比（），从控制流速上阻断羊群效应。

- **收敛性定理（Theorem 1）**

  构造联合考量路由状态与实际在途负荷的复合 Lyapunov 函数。数学证明：在任意固定网络延迟下，当时间窗口时，系统平均负载与理论社会最优解之间的距离以阶收敛至 0。该结论从理论上终结了广域网自适应路由必然震荡的疑虑。

### 5.3 容错与过载保护机制

- **动态避错率（Error Aversion Rate）**

  Leaf 实时统计 HTTP 5xx、OOM 等报错率并回传，Root 动态维护各 Cell 的避错因子（0~1），在节点异常时毫秒级平滑卸载流量，恢复后平滑回升。

- **边际阻断机制**

  基于梯度的成本函数在节点接近算力红线时成本趋近于无穷大，形成坚固的软件防堤，杜绝推理引擎因并发击穿导致的显存溢出（OOM）。

- **轻量级无状态容错**

  Root 和 Leaf 故障均可瞬间由同域 Peer 副本接管，状态自愈周期在微秒至毫秒级。

## 6\. 生产落地实测与实验评测结果

### 6.1 谷歌大规模生产环境迁移实测

在 Google 全球 68 个生产模型端点（覆盖数万个观测周期）由 MNLB 迁移至 DLB 的固定效应面板回归分析（Fixed-Effects Panel Regression，控制流量与模型变量）中，取得了显著的因果性能提升（）：

- **集群负荷提升**

  在满足相同严格 SLA 的前提下，DLB 支撑全网集群平均运行利用率**提升了 20%（Run 20% Hotter）**。

- **高峰期压制**

  在每日白天高峰期，算力利用率频繁冲高至 90% 以上，DLB 仍能将平均端到端时延平稳压制在约 1 秒左右，彻底杜绝了旧架构下的延迟暴冲。

### 6.2 系统运行开销（Overhead）

- **计算成本极低**

  全网所有运行 DLB 软件路由器的 CPU 资源占用，仅占其所调度的大模型 MLA **硬件算力成本的 0.04%（约 1/2500）**。

- **转发延迟极短**

  请求穿透 Root Router 和 Leaf Router 引入的额外转发耗时仅为**数百微秒至 1 毫秒**，占大模型端到端耗时的比例不足 0.05%。

### 6.3 极端场景基准测试与消融实验

1. **应对突发流量（95% 利用率突发）**

   旧版 MNLB 因数秒至数十秒的控制延迟，导致局部队列积压溢出，报错率飙升至 1.3%；DLB 秒级异地分流，报错率维持在近乎 0%。

2. **应对节点容量故障**

   在突然削减节点副本模拟宕机时，MNLB 引发大面积长尾暴冲和近 3% 报错；DLB 依靠毫秒级避错率机制实现无缝引流，错误率接近 0%。

3. **抗噪鲁棒性消融**

   在引入高达 60% 乘性噪声的人为干扰下，基于梯度的策略（Flow-Grad）性能优雅降级，依然显著超越传统基线；而基于在途数的策略（Disc-RIF）完全免疫时延估计误差，表现出极强的工业鲁棒性。

## 7\. 总结与架构启示

Google DLB 的成功落地为 AI 原生时代的高性能网络架构提供了极具价值的范式参考：

1. **算网协同从粗粒度走入微观控制**

   网络调度不再仅仅感知网络带宽与 RTT，而是深入感知模型执行队列（RIF）、计算阶段（Prefill vs Decode）以及前缀复用状态。

2. **黑盒连续化建模替代白盒静态配置**

   采用参数化凸模型（Softplus）将极端异构、瞬息万变的大模型底层计算黑盒化抽象，实现自适应在线学习。

3. **理论与工程的双重闭环**

   离散贪心（重型任务）与连续梯度投影（轻量流式任务）分类治理，配合基于 Lyapunov 的全局收敛证明，既保证了毫秒级的极致响应速度，又杜绝了分布式系统在广域网反馈滞后下的流量震荡顽疾。
